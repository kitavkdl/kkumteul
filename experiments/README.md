# 실험 카드 (experiments)

실험 카드는 "이 세계에 이 각본을 줬더니 이렇게 됐다"를 정해진 양식으로 적은 작은 기록이다.
한 폴더에 카드 하나(`experiments/<이름>/card.json`, `card.md`)가 들어간다. 사람이 손으로 쓰지 않고 명령이 쓴다.

## 카드 만들기

```bash
python3 -m kkumteul.experiment --from runs/base --scenario scenarios/drought.json --steps 200000 --name my-drought
```

이 명령이 하는 일:

1. `--from`의 체크포인트(실행 폴더를 주면 가장 최근 것)에서 두 갈래를 만든다.
   `runs/exp-<이름>-control`은 각본 없이, `runs/exp-<이름>-treatment`는 각본을 주고 돌린다. 난수 흐름은 둘이 같다.
2. 두 갈래를 `--steps` 스텝씩 돌린다(차례로). 도중에 멈췄으면 같은 명령을 다시 치면 이어 간다.
   다 돌린 뒤에 겨루기 옵션(`--reps` 등)만 바꿔 다시 치면 겨루기만 다시 하고 카드를 새로 쓴다.
   길이·각본·출발점이 다르면 같은 이름으로는 돌릴 수 없다(`--name`을 새로 준다).
3. 각본을 겪은 쪽의 생존자와 대조 쪽의 생존자를 바탕 설정의 새 세계에 같은 수로 풀어 겨루게 한다.
   한쪽이 20마리 아래면 겨루지 않고 그렇게 적는다.
4. `experiments/<이름>/`에 카드를 쓴다.

| 옵션 | 뜻 | 기본값 |
|---|---|---|
| `--from` | 출발점: 실행 폴더나 체크포인트 npz | 꼭 있어야 한다 |
| `--scenario` | 각본 json | 꼭 있어야 한다 |
| `--steps` | 두 갈래를 각각 돌릴 스텝 수 | 꼭 있어야 한다 |
| `--name` | 실험 이름(영문자·숫자·점·밑줄·붙임표) | 꼭 있어야 한다 |
| `--at` | 갈라낼 체크포인트의 스텝 | 가장 최근 |
| `--reps`, `--assay-steps`, `--n`, `--assay-seed` | 겨루기 반복 수, 한 판의 길이, 한쪽 개체 수, 난수 씨앗 | 4, 8000, 400, 1000 |
| `--out`, `--runs` | 카드를 쓸 폴더, 두 갈래의 실행 폴더를 만들 곳 | `experiments`, `runs` |

## 카드에 적히는 것

| 항목 | 내용 |
|---|---|
| `scenario` | 각본 전체(이름, 설명, 사건)와 내용 해시. 카드만 있어도 같은 각본을 다시 만들 수 있다 |
| `parent` | 출발한 체크포인트의 파일 이름, sha256, 스텝 |
| `seed`, `steps`, `config_diff_from_default` | 세계 씨앗, 돌린 길이, 기본 설정과 다른 값 |
| `code_version`, `source_hash` | 코드 판과 계산 코드(`rng.py`, `config.py`, `kernels.py`)의 해시 |
| `arms.control`, `arms.treatment` | 갈래마다: 개체 수 최소·최대·끝, 재주입 수, 출생 비, 운석으로 죽은 수, 쌓인 세대(평균 계보 깊이 증가), 평균 활성 뉴런 처음 → 끝, Fitness Transmission 평균 |
| `assay` | 겨루기 결과: r(각본 − 대조)의 평균과 표준오차, 같은 무리끼리 겨룬 값(잡음), 판마다 끝 개체 수 |
| `verdict` | 판정 한 줄 |
| `how_to_read` | 읽는 법 |

카드에는 날짜, 속도, 파일 경로처럼 기계마다 달라지는 값을 넣지 않는다. 같은 기계에서 같은 명령을 다시 치면 같은 카드가 나온다.
다른 기계에서는 숫자가 조금 다를 수 있다(다른 기계 사이의 비트 단위 재현은 보장하지 않는다).

## 읽는 법

- 뇌 크기 같은 형질의 추세는 성장의 증거가 아니다. 선택이 없어도 변한다. 판정은 겨루기로 한다.
- 재주입이 있었다면 그 개체군은 스스로 유지되지 못한 것이다. "버텼다"가 아니라 "채워 넣었다"로 읽는다.
- 겨루기의 r이 양수면 각본을 겪은 쪽이 평소 세계에서 더 잘 는다. 같은 무리끼리 겨룬 값이 0에서 멀면 측정 자체가 기운 것이다.
- 한쪽이 전멸한 판은 r의 크기가 아니라 "전멸"만 읽는다.
- 한 번, 한 씨앗의 결과다. 더 자세한 것은 README의 "측정값을 읽을 때".

## 카드 올리기 (pull request)

1. 이 레포를 포크하고 가지를 만든다.
2. 올릴 파일:
   - `experiments/<이름>/card.json`, `experiments/<이름>/card.md` (명령이 쓴 그대로. 손으로 고치지 않는다)
   - 새 각본을 썼다면 `scenarios/<각본>.json`
   - 하고 싶은 말(왜 이 조건을 골랐는지, 화면에서 본 것)은 `experiments/<이름>/notes.md`에 따로 적는다
3. 올리지 않는 것: `runs/` 폴더(체크포인트와 기록은 크다. git에 올라가지 않게 되어 있다), 생물 묶음(`.npz`).
   묶음을 나누고 싶으면 pull request 글에 내려받을 곳을 적는다.
4. 이름은 겹치지 않게 짓는다(예: `drought-seed7-200k`). 같은 이름의 카드를 덮어쓰지 않는다.
5. pull request 글에 출발점을 어떻게 만들었는지 적는다(예: `python3 -m kkumteul.run new --run runs/base --steps 200000`, 기본 설정).
   다른 사람이 같은 출발점을 만들 수 있어야 비교할 수 있다. 공개된 "씨앗 세계"에서 출발했다면 그 이름을 적는다.

카드에 개인 정보나 자기 컴퓨터의 경로가 들어가지 않는지 올리기 전에 한 번 본다(명령이 쓴 카드에는 들어가지 않는다).

## 생물 묶음으로 겨루기

각본을 겪고 살아남은 생물을 다른 사람의 생물과 겨루게 하려면 묶음을 만든다.

```bash
python3 -m kkumteul.pack export --from runs/exp-my-drought-treatment --out my-drought.pack.npz --label "가뭄 20만 스텝"
python3 -m kkumteul.pack info my-drought.pack.npz
python3 -m kkumteul.measure assay --a my-drought.pack.npz --b someone-else.pack.npz
```

묶음에는 뽑은 개체의 유전체와 겨룰 세계의 설정만 들어 있다(기본 설정에서 400마리면 약 9MB. 체크포인트는 약 77MB다). 감각 칸 수와 뇌 최대 크기 설정이 같은 세계에서 나온 묶음끼리만 겨룰 수 있다.
겨루는 세계는 B 쪽 묶음의 설정으로 만든다.
