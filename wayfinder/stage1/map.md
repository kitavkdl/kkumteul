# 시뮬레이션 1단계 — 지도
마지막 갱신: 2026-11-04 (밤, 구현 뒤)

## 목적지
1단계(2D 세계 + 몸 + 죽음/번식 + 뇌 비용 + 감각 한계)가 N5 Air에서 24시간 돌고 있고, 성장 측정·저장/분기·관찰 화면이 붙어 있는 상태.
설계 문서에서 멈추지 않고 실제 가동까지 간다(사용자 결정 2026-11-04).

## 메모
- **실행까지 포함.** 이 지도는 결정뿐 아니라 만들기·가동까지 다룬다. 다만 만들기 쪽 티켓은 설계 문서가 나온 뒤에 세운다.
- **네 갈래 모두 사용자와 문답으로 정한다**(2026-11-04): 관찰 화면·성장 측정 / 생물(몸·감각·뇌) / 세계 규칙 / 실행·운영. 조사와 실측만 혼자 한다.
- **구현부터 간다**(2026-11-04 밤, 사용자): 위 "문답으로 정한다"를 바꿨다. 조사(`reports/인공생명 1단계 구현 결정.md`) 결과로 Claude가 기본값을 정해 바로 구현한다. 각 티켓에는 "임시 결정(사용자 확인 전)"으로 적고 값은 설정 파일로 빼서 나중에 문답으로 뒤집을 수 있게 한다.
- **코드 자리**: 처음에는 비공개 작업 레포 안에 두었다가 2026-11-05에 이 레포(`kkumteul`, 공개)로 옮겼다. 이름과 공개는 사용자가 정하셨다.
- 지도 이전에 정해진 것은 설계 노트 0장에 있다: `docs/design-notes-2026-10-28.md`
  (2026-11-04 현재 서버 `(비공개 작업 레포)`에만 있고 커밋되지 않았다. 맥에서는 안 보인다.)
  - 목적: 아무도 가르치지 않았는데 생물들이 스스로 행동·전략·신호를 만들어 내는 것
  - 속도: 현실 하루에 10세대. 장소: N5 Air 24시간 가동. 정밀도: 가능한 한 정교하게
  - 1단계는 2D 연속 공간, 물리 직접 구현, Python+numpy 배열 일괄 계산(10/29) — [출발점 정하기](T05-starting-point.md)에서 조사 결과에 비추어 다시 본다
  - 단계 순서: 1 세계·몸 → 2 마음 → 3 사회 → 4 판이 바뀌는 세계. 성장 측정·저장/분기·관찰 화면은 항상 둔다
  - 코드는 GitHub public 레포로 올릴 생각. 레포·LXC를 만들기 전에는 설정을 먼저 보고한다(규칙 A)
- 무거운 실험은 서버에서 메모리 상한을 걸고 돌린다([실행 기계 자원](T04-host-resources.md)).
- **사용자가 보고 싶어 하시는 것**(2026-11-04 밤): 개체들이 자기들끼리 소통해서 법·규제나 학교 같은 것을 만드는 것, 이 세계를 만든 이에 대해 궁금해하는 것, 지구와 닮은 철학이 나오는 것. 최종 목표는 아니고 "있으면 더 재미있을 것", 다른 다양한 것도 다 좋다고 하셨다.
  Claude가 드린 답: 신호·규범(벌주기)·가르침의 원시적인 형태는 3단계(신호·문화 전달·혈연)에서 기대할 수 있다. 만든 이에 대한 물음이나 철학은 언어 수준의 사고가 필요해서 작은 진화 신경망으로는 선례가 없고, 언어 모델 기반 개체를 같은 세계에 얹는 별도 갈래가 필요하다(그 경우 철학은 사람 글에서 빌려온 것이 된다, 설계 노트 3-2). 3단계 지도를 세울 때 선택지로 올린다.
- 조사 결과는 `research/`와 `research_notes/`·`reports/`(11/04 deep-research), 시제품 코드는 ``에 둔다. 실행 결과 `runs/`는 git에 올리지 않는다.
- **임시 결정**: 티켓 상태가 "임시 결정 (사용자 확인 전)"이면 Claude가 조사 결과로 정해 구현까지 한 것이다. 사용자가 뒤집으시면 `kkumteul/config.py`의 값을 바꾼다.
- 용어
  - **붙이기(겨루기)**: 옛 개체와 지금 개체를 같은 수로 새 세계에 풀어 어느 쪽 후손이 더 느는지 보는 것(설계 노트 5-F, [성장 측정 방법](T14-growth-measure.md)).
  - **세대**: 살아 있는 개체의 평균 계보 깊이(자식 = 부모 + 1). [죽음·번식·세대 정의](T09-death-reproduction-generation.md).
  - **대조 실행**: 본 실행과 같은 수의 출생·사망을 무작위 개체에 적용하는, 선택 없는 실행.
  - **재주입**: 개체 수가 하한 아래로 떨어졌을 때 살아 있는 개체의 변이 복제본을 넣는 것. 횟수를 기록한다.

## 아직 못 정한 것 (안개)
- **"하루 10세대"의 뜻.** 지금 값으로는 하루 수만 세대가 쌓인다. 빠르게 많이 진화시킬지, 한 개체가 오래 살아 눈으로 따라갈 수 있게 할지는 사용자가 정하실 일이다([죽음·번식·세대 정의](T09-death-reproduction-generation.md)).
- 성장 측정을 가동본에서 얼마나 자주 자동으로 돌릴지, 씨앗만 다른 독립 실행을 같이 둘지.
- 개체 수와 세계 크기의 최종 숫자. 속도·램은 제약이 아니라고 나왔다(맥 실측). 화면으로 보기 좋은 크기와 진화가 잘 되는 크기로 정할 문제다.
- 실행 자리 만들기·설치·서비스 등록([실행 자리 정하기](T16-where-to-run.md), 초안 `deploy/kkumteul.service`). 만들기 전에 설정을 보고한다.
- 가동한 뒤 지켜보기: 멈췄을 때 알림, 체크포인트를 시간별→일별로 솎기.
- **출생·사망 기록을 얼마나 남길지.** 전속으로 돌리면 하루 약 6.7GB가 쌓인다(맥 기준). 속도를 늦출지, 오래된 기록을 지울지는 "하루 10세대"의 뜻과 같이 정할 일이다.
- 허점 악용을 막을지 자연 법칙으로 받아들일지, 가동 중 언제 손대도 되는지(설계 노트 5-F ☆). 1단계에서 정할 일인지부터 불분명하다.
- 2단계(호르몬·기억)가 들어올 자리를 1단계 코드에 얼마나 미리 비워 둘지.
